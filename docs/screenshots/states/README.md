# 五态截图（UX-01 验收证据）

对应 `docs/ui/06-states.md`，用于证明 15 个页面的关键数据区都能落到「正常 / 加载 / 空 / 失败 / 无权限」五种状态，且空与失败的措辞没有混用。

## 文件对照

| 文件 | 页面 | 状态 | 说明 |
|------|------|------|------|
| `trips-1-normal.png` | 行程记录 | 正常 | 有数据、统计卡与筛选条齐全 |
| `trips-2-empty.png` | 行程记录 | 空 | 「还没有行程记录」+「去上报行程」，副标题同步清空避免与空态冲突 |
| `trips-3-error.png` | 行程记录 | 失败 | 「加载失败 · 请求超时（50001）」+ 重新加载 |
| `trips-4-loading.png` | 行程记录 | 加载 | 骨架屏，保持布局不跳动 |
| `points-1..3` | 积分明细 | 正常/空/失败 | 空态文案「还没有积分变动」 |
| `mall-1..3` | 积分商城 | 正常/空/失败 | 空态文案「礼品都被兑完了，等补货中」 |
| `orders-1..3` | 我的订单 | 正常/空/失败 | 空态带「去商城看看」 |
| `trip-detail-1..3` | 核算明细 | 正常/空/失败 | 空态为「行程不存在或已被删除」（越权也走这条，不暴露存在性） |
| `dashboard-1..5` | 运营概览 | 正常/空/失败/加载/无权限 | 管理端代表页 |
| `admin-orders-1..3,5` | 订单处理 | 正常/空/失败/无权限 | 取消原因必填见 `web-cancel-modal` |
| `users-1..3` | 用户管理 | 正常/空/失败 | 搜索无结果与全无用户分开写 |

完整交互（差异表、读取失败 50001、取消原因弹窗）请看页面本身：`prototype-web/admin/reconciliation.html`、`prototype-web/admin/orders.html`。

## 状态是怎么造出来的

截图不是手工 P 的，也不是改产品代码。做法是：复制页面到同目录的临时文件，在 `</body>` 前注入一段只在截图时生效的脚本，把 `<main>` 里的数据区替换成目标状态（保留页头），用 headless Chrome 截完即删临时文件。**仓库里不含任何注入代码**，产品页面保持原样。

## 口径

- 「空」= 请求成功但没数据；「失败」= 请求没成功。两者的图标、主文案、是否带重试按钮都不同。
- 「无权限」只出现在管理端页面；用户端越权统一按 404 处理。
- 截图基准 1440×900 / 1440×1000，与 `docs/ui/02-design-system.md` 的画布一致。
