# 用例分析

## 1. 角色分析

| 编号 | 角色 | 所属范围 | 职责与目标 |
| --- | --- | --- | --- |
| ACT-01 | 用户 | 城市居民 | 注册登录、上报模拟绿色出行、查看减排量和积分、兑换商品 |
| ACT-02 | 商户 | 积分商城供应方 | 提供商品、维护可兑换库存、处理兑换订单 |
| ACT-03 | 运营管理员 | 平台运营方 | 配置碳核算规则、管理用户和商品、处理异常、查看统计 |

## 4. 关键用例详细说明

### 4.1 UC-04 上报模拟行程

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户 |
| 优先级 | P0 |
| 目标 | 保存一条绿色出行记录，计算并发放本次碳积分 |
| 触发条件 | 用户提交一条模拟行程 |
| 前置条件 | 用户已登录且账户处于启用状态 |
| 后置条件 | 行程保存成功；规则快照保存；积分流水生成；账户余额增加 |

主成功场景：

1. 用户选择出行方式，填写里程、起点、终点和起止时间。
2. 系统校验身份和账户，检查 `userId + clientTripId`：同键同输入重放原结果，同键不同输入拒绝；新请求再校验必填项、里程和时间。
3. 系统根据行程结束时间和出行方式匹配规则，采用 `[effectiveFrom, effectiveTo)` 区间。
4. 系统计算基准排放、实际排放、碳减排量和本次积分。
5. 系统保存行程、规则版本和计算结果快照。
6. 系统以唯一约束防止并发重复，并按内部行程编号创建唯一发放流水；零积分不建流水。
7. 非零积分更新余额，行程标记POINTED；行程、快照、流水和余额在同一事务提交，零积分不改余额。
8. 事务提交成功后，返回行程结果、减排明细和新余额。

异常与替代流：

- 输入不合法：拒绝提交并返回具体字段错误。
- 账户已停用：拒绝提交。
- 当前出行方式没有生效规则：拒绝发放积分，不保存半成品记录。
- 客户端行程号已处理：同用户同键同输入返回已有结果，不同输入拒绝；并发重复只提交一次。
- 保存流水或更新余额失败：事务回滚，不留下部分数据。

业务规则：

- 支持 `BUS`、`SUBWAY`、`BIKE`、`WALK` 四种方式。
- 模拟里程必须大于 0，课程原型暂定上限200公里，最多3位小数；上限非教师规定。
- 起止时间必须有效，结束时间必须晚于开始时间且不得晚于服务器当前时间；起终点必填。
- 每条行程必须保存核算规则版本和因子快照。

### 4.2 UC-11 兑换积分商品

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户 |
| 优先级 | P0 |
| 目标 | 扣减积分和库存，生成兑换订单 |
| 触发条件 | 用户确认兑换某个商品 |
| 前置条件 | 用户已登录且账户启用；新请求需商品上架且余额库存充足；幂等重放按BR-05返回原订单 |
| 后置条件 | 积分余额、商品库存、积分流水和兑换订单保持一致 |

主成功场景：

1. 用户选择商品和兑换数量，并提交兑换请求。
2. 系统校验 `userId + requestId`，同键同商品同数量重放原订单，不同输入拒绝。
3. 系统读取商品状态、库存和所需积分。
4. 系统校验余额与库存是否满足兑换数量。
5. 系统原子扣减积分和库存。
6. 系统创建兑换订单和积分扣减流水。
7. 系统返回订单号和最新余额。

异常与替代流：

- 余额不足：返回失败，不改变余额和库存。
- 库存不足：返回失败，不改变余额和库存。
- 商品已下架：拒绝兑换。
- 同一请求号重复到达：返回第一次处理结果，不重复扣减。
- 任一步骤失败：整个事务回滚。

业务规则：

- 积分不可提现、不可转让。
- 兑换订单创建后立即扣减积分和库存。
- 订单状态只允许按 `CREATED → FULFILLED` 或 `CREATED → CANCELLED` 流转。
- 仅运营管理员可取消未履约订单；原积分全额返还、原数量库存恢复、订单取消及唯一冲正流水同事务提交。重复取消不再次返还，已履约拒绝取消，商品下架不影响返还。

### 4.3 UC-09 配置碳核算规则

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 运营管理员 |
| 优先级 | P0 |
| 目标 | 新增或更新可追溯的碳核算规则 |
| 触发条件 | 运营管理员提交规则变更 |
| 前置条件 | 管理员已登录并具有规则管理权限 |
| 后置条件 | 新规则保存、版本唯一、生效时间明确，历史行程结果不变 |

主成功场景：

1. 管理员选择出行方式和基准交通方式。
2. 管理员填写基准排放因子、实际排放因子、积分系数和生效时间。
3. 系统校验数值非负、生效时间合法，并与同方式规则区间不冲突。
4. 系统创建新的规则版本。
5. 系统在生效时间到达后使用新版本；历史行程继续引用旧版本快照。

异常与替代流：

- 数值为负或缺少必填项：拒绝保存。
- 生效区间冲突：要求管理员调整时间或明确结束旧规则。
- 规则已存在且不允许修改：只能创建新版本，不能覆盖历史版本。

### 4.4 UC-14 处理兑换订单

前置条件：运营管理员已登录，订单存在。将CREATED改为FULFILLED，或填写原因改为CANCELLED。履约与取消均记录处理人、时间和审计信息；取消还须按订单原成本返还积分与库存、追加冲正，整体原子提交。重复相同操作返回原结果，终态之间不可转换；履约与取消竞争只能一个成功。处理历史订单不要求商品仍上架。

### 4.5 UC-17 核对积分账目

前置条件：运营管理员已登录。在同一一致性快照内读取账户、流水、成功行程及订单，比较余额、流水数量及金额，返回差异明细或无差异。结果包含核对时间、对象和口径；不自动修账。读取失败应报告核对失败，不返回不完整的无差异结论。规则见BR-07。

### 4.6 UC-01 注册账号

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户 |
| 优先级 | P0 |
| 目标 | 建立一个用户名唯一、可以登录的普通用户身份 |
| 触发条件 | 未登录访客在注册页提交注册表单 |
| 前置条件 | 用户名未被占用 |
| 后置条件 | 账号以启用状态创建，角色为普通用户；密码只保存带盐哈希；积分账户余额为0 |

主成功场景：

1. 访客填写用户名、密码、昵称等必填资料并提交。
2. 系统校验必填项、用户名格式和密码长度。
3. 系统检查用户名是否已被占用。
4. 系统生成随机盐，计算密码哈希后保存，不保存明文。
5. 系统创建角色为普通用户、状态为启用的账号，同时创建余额为0的积分账户。
6. 系统返回注册成功，访客随后通过 UC-02 登录。

异常与替代流：

- 用户名已被占用：拒绝注册并提示更换用户名。
- 必填项缺失或格式不合法：拒绝提交，按字段返回具体错误。
- 并发注册同一个用户名：由唯一约束保证只有一条成功，另一条按"用户名已存在"拒绝。
- 保存账号或积分账户失败：事务回滚，不留下只有账号没有账户的半成品。

业务规则：

- 用户名全局唯一，由数据库唯一约束兜底，不能只靠先查询后插入。
- 密码只保存带盐哈希，接口响应、日志和审计记录都不出现明文密码。
- 新用户角色固定为普通用户，不提供自助提升为管理员的入口。
- 注册接口允许匿名访问，其余接口按 BR-08 校验角色与资源归属。

### 4.7 UC-02 登录系统

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户、运营管理员 |
| 优先级 | P0 |
| 目标 | 校验凭据并建立只授权当前角色功能的会话 |
| 触发条件 | 用户在登录页提交用户名和密码 |
| 前置条件 | 账号已注册 |
| 后置条件 | 校验通过时返回会话令牌、角色和基本资料；校验失败时不建立任何会话 |

主成功场景：

1. 用户提交用户名和密码。
2. 系统按用户名查找账号，并对不存在的情况同样执行一次哈希比对，使响应耗时不暴露账号是否存在。
3. 系统比对密码哈希。
4. 系统检查账号状态为启用。
5. 系统签发会话令牌，返回角色和基本资料。
6. 用户进入与角色对应的首页：普通用户进入行程页，运营管理员进入运营页。

异常与替代流：

- 用户名不存在或密码错误：统一返回"用户名或密码错误"，不区分具体原因。
- 账号已停用：拒绝登录并提示联系管理员。
- 会话过期或令牌无效：要求重新登录，不返回任何业务数据。
- 已停用用户持旧会话继续操作：请求被拒绝，此行为在启停用户功能实现后生效。

业务规则：

- 失败提示不得暴露账号是否存在，也不得回传密码哈希等内部字段。
- 按 BR-08 校验：普通用户只能访问本人数据，管理员才能进入规则、商品与订单管理；前端隐藏按钮不作为权限依据。
- 会话令牌在每次受保护请求上由服务端校验，角色以服务端记录为准，不信任请求中携带的角色字段。

### 4.8 UC-03 维护个人资料

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 用户 |
| 优先级 | P1 |
| 目标 | 查看并修改本人可编辑的基础资料 |
| 触发条件 | 用户打开个人中心，或保存修改后的资料 |
| 前置条件 | 用户已登录且账户处于启用状态 |
| 后置条件 | 本人资料被更新；用户名和角色保持不变；历史行程与积分快照不受影响 |

主成功场景：

1. 用户进入个人中心。
2. 系统按会话身份查询并返回本人资料。
3. 用户修改昵称等可编辑字段并保存。
4. 系统校验字段合法性，并按会话身份定位记录、只更新本人数据。
5. 系统返回更新后的资料。

异常与替代流：

- 尝试修改用户名或角色：拒绝，这两个字段对普通用户只读。
- 请求中携带他人用户编号：按会话身份覆盖，越权修改被拒绝。
- 未登录或会话已失效：跳转登录，不返回资料。
- 字段超长或含非法字符：拒绝保存并返回具体字段错误。

业务规则：

- 服务端用会话身份定位要修改的记录，忽略请求体中的用户编号，避免越权修改。
- 用户名与角色不可由普通用户修改，只能由管理员在后续功能中处理。
- 资料修改只影响用户表，不回写行程、流水和订单中的历史快照。
