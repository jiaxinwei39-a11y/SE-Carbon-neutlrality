# 业务规则与验收基线

版本v0.2；2026-10-27。以下是待实现的需求与预期结果，不表示软件已实现或测试已通过。

## 1. 统一业务规则

### BR-01 行程与规则时间

支持BUS、SUBWAY、BIKE、WALK。起终点必填；里程大于0、最多3位小数，暂定上限200公里（项目假设，非教师规定）。满足 `startTime < endTime <= 服务器当前时间`。业务时区Asia/Shanghai，存储保留明确时区语义。

按行程endTime匹配同方式规则：`effectiveFrom <= endTime < effectiveTo`；末版effectiveTo允许为空表示无穷远。历史补录使用历史版本；跨生效时刻的整条行程按结束时刻版本核算，不拆分。无匹配规则时整笔失败。

已发布因子不可覆盖。新规则不得追溯生效；切换时在同一事务结束旧区间、创建新区间，同方式区间不重叠。停用只结束后续覆盖，不删除历史版本，也不妨碍补录匹配历史区间。记录操作人、时间、变更前后值与原因；历史行程快照不变。

### BR-02 核算与精度

```text
基准排放 = 距离 × 基准因子
实际排放 = 距离 × 出行方式因子
减排量 = max(0, 基准排放 - 实际排放)
发放积分 = floor(减排量 × 每千克积分系数)
```

使用十进制计算，禁止二进制浮点直接入账。距离最多3位小数、因子和积分系数最多6位小数，超精度拒绝；排放结果保存9位小数，最后只取整一次。页面可显示6位小数并标为展示舍入值，明细保留原精度，积分不使用展示舍入值计算。

因子与系数非负；零减排或取整后零积分仍保存POINTED行程，不生成零金额流水，余额不变。MVP无每日上限、倍率、过期、转让和提现。

### BR-03 行程幂等

客户端首次提交前生成clientTripId，重试复用。唯一范围 `userId + clientTripId`；同键且方式、里程、起终点、起止时间规范化后相同，返回原结果；不同输入拒绝。先检查身份、启用状态和归属，再重放已有成功结果，不按新规则重算。并发首次提交只允许一笔提交。

仅服务器生成tripId不能识别重试；换新客户端号重复填报属于模拟真实性限制，不宣称已实现反作弊。

### BR-04 发分原子性

行程、因子与规则快照、非零发放流水、余额同事务提交，任一步失败整体回滚。每条行程至多一笔TRIP_GRANT，零积分无流水。失败只返回错误与日志，不保存失败行程。

### BR-05 兑换

数量为正整数，单价为正整数。唯一范围 `userId + requestId`；同键同商品同数量返回原订单（包括商品后来下架或改价），不同输入拒绝；重放也检查身份、启用状态和订单归属。

新兑换检查上架状态、库存和余额，按服务器读取价格计算成本，保存pointsPriceSnapshot与pointsCost。订单、REDEMPTION_DEBIT、余额、库存同事务提交；余额不足、库存不足或任一步写入失败均无部分变更。并发不能透支或超卖，不采用跨服务预占和分布式补偿。

### BR-06 履约与取消

仅运营管理员可把CREATED改为FULFILLED或CANCELLED。记录processedBy、processedAt，取消必须填写processReason。取消按原pointsCost全额返还积分、原quantity恢复库存、追加唯一REDEMPTION_REVERSAL，并更新状态和审计，全部同事务提交。

重复取消返回原结果、不重复返还；已履约拒绝取消，已取消拒绝履约；履约与取消并发只能一个成功。使用原订单成本而非现价，下架不影响返还；有关联订单或流水的商品只能下架，不物理删除。任一步失败全部回滚。

### BR-07 清算、对账与商户汇总

积分清算为发放、扣减、冲正和对账，不含真实资金结算。初始余额0，不允许无流水改余额。

- 余额等于全部流水changePoints之和。按账户内事务确定的顺序累计，应等于各条balanceAfter；实验二确定排序键，不能只靠可能相同的时间戳。
- 非零成功行程恰好一笔TRIP_GRANT，金额等于awardedPoints；零积分行程无流水。
- 每个订单恰好一笔REDEMPTION_DEBIT，金额等于负pointsCost；CANCELLED再有一笔REDEMPTION_REVERSAL，金额等于pointsCost。
- `businessType + businessId`唯一；发放关联tripId，扣减和冲正关联orderId；流水只追加、不改删。
- 对账在同一一致性快照读取账户、流水、行程及订单，逐项比较并返回对象、期望、实际值和核对时间；只读、不自动修复。读取失败须报告核对失败。
- P1商户汇总按processedAt左闭右开区间，只统计当前FULFILLED订单，按商品商户归属汇总数量与消耗积分，排除CREATED和CANCELLED；不形成现金应付款。

### BR-08 权限与审计

MVP仅普通用户、运营管理员登录。商户保留为外部利益相关者和商品归属，由管理员代办；图中“商户（管理员代办）”不代表独立登录接口。

用户仅访问本人数据；管理员配置规则、维护商品库存、处理订单并对账。注册登录允许匿名，其余按角色与资源归属校验。启停用户为P1，实现后应立即阻止停用用户持旧会话继续操作。规则、库存、订单审计与业务原子保存，含操作人、时间、前后值及原因。

## 2. 核算验收样例

测试夹具（非官方因子）：R-A基准0.200000 kgCO2e/km，公交0.050000，积分系数10.000000；R-B仅把积分系数改为20.000000。

| 编号 | 输入或条件 | 期望结果 |
| --- | --- | --- |
| TC-01 | R-A，公交10km | 基准2.000000000，实际0.500000000，减排1.500000000，积分15 |
| TC-02 | R-A，公交0.333km | 减排0.049950000，积分0；行程成功，无流水 |
| TC-03 | 实际因子0.250000，其余同R-A，10km | 减排0、积分0，不出现负值 |
| TC-04 | 零或负里程、超过200km、超精度、非法方式、空起终点、时间逆序或未来结束 | 各输入分别拒绝，无业务变更 |
| TC-05 | R-A到2026-11-01 00:00结束，R-B同刻开始；10km分别在边界前和边界时结束 | 分别15和30分；历史补录仍15；跨界按结束时间取R-B；测试时钟设在边界之后 |
| TC-06 | 无匹配规则、负因子、重叠区间、追溯生效 | 分别拒绝，无部分业务或规则修改 |

## 3. 流程验收场景

下表仅为预期结果，尚未执行。

| 编号 | 输入或操作 | 期望结果 |
| --- | --- | --- |
| TC-07 | 同用户同clientTripId重试、并发首次提交；同键不同输入 | 一条行程、至多一笔发分；重放原结果，不同输入拒绝 |
| TC-08 | 不同用户用同clientTripId；越权查行程 | 用户间键不冲突，越权拒绝 |

| TC-13 | 发分、兑换、取消分别在流水或余额写入处故障注入 | 各整笔事务回滚，无部分行程订单冲正库存变更 |

| TC-15 | 取消TC-09订单、重复取消、改价或下架后取消 | 恢复50分库存2，仅一笔+20冲正；原成本返还 |
| TC-16 | 已履约取消、已取消履约、并发履约与取消 | 非法转换拒绝；并发仅一个成功且账目与终态一致 |
| TC-17 | 切换规则后查旧行程与同键重试；覆盖已发布因子 | 旧快照积分不变、返回原结果、覆盖拒绝 |
| TC-18 | 普通用户访问管理接口或他人积分订单；停用后旧会话操作 | 越权拒绝；启停功能实现后旧会话也拒绝 |
| TC-19 | 汇总含三种订单状态和区间边界 | 仅计入区间内已履约订单，与明细一致 |
| TC-20 | 重复用户名注册、正确错误登录、越权改资料、商品新增下架、个人明细查询 | 唯一注册与安全登录、资料隔离、商品合法性和上下架生效、本人行程积分订单与快照一致 |

测试余额通过有效业务流水建立，不直接改余额；只有TC-14差异注入可在隔离环境故意破坏数据。真实测试报告须记录环境、实际输出、测试时间和测试人，按指导书采用基本路径法与等价类划分法，不能把预期结果当作通过证据。
