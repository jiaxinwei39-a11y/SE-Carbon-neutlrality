# 界面五态规范（UX-01 · 验收项 ①）

> 适用：`prototype-web/` 全部页面。每个「数据区」（一个列表、一张卡片、一组图表）都必须能画出下面五种状态。
> 对照页：`prototype-web/states.html`。

## 1. 五种状态

| # | 状态 | 触发条件 | 视觉 | 必须有的元素 |
|---|------|----------|------|--------------|
| 1 | 正常 | 请求成功且有数据 | 内容按设计规范排版 | 数据本身 + 可执行操作 |
| 2 | 加载中 | 请求未返回且 < 8s | 骨架屏（`.skel`），保持布局结构 | 无文字，不出现 0 或「暂无」 |
| 3 | 空 | 请求成功但结果为空 | `.empty`：图标 + 一句主文案 + 行动 | 区分「还没有」与「没有符合条件」 |
| 4 | 失败 | 网络错误 / 5xx / 超时 > 8s | 图标 + 一句人话 + 错误码 + 重试 | 可点击的「重新加载」 |
| 5 | 无权限 | 403 | 锁图标 + 说明谁没权限 + 出口 | 回首页 / 切换账号 |

## 2. 文案规则

| 状态 | 允许 | 禁止 |
|------|------|------|
| 加载中 | 骨架屏；分页刷新用顶部细进度条 | 「加载中…」文字配合空白页；转圈超过 8 秒 |
| 空（首次） | 「还没有行程记录」+「去上报行程」 | 「暂无数据」「null」「[]」 |
| 空（筛选） | 「没有符合条件的行程」+「清除筛选」 | 与首次空用同一句文案 |
| 失败 | 「加载失败 · 请求超时，可重试」 | 显示成空列表；只弹一个「系统异常」 |
| 无权限 | 「当前账号是普通用户，管理端仅对运营管理员开放（40301）」+ 出口 | 只显示 403 或直接跳走不解释 |

判定口径：**空 = 请求成功但没数据；失败 = 请求没成功**。两者视觉与文案都不能混，否则等于把故障报成「没数据」。

## 4. 三个专项约定

### 4.1 核算明细（`app/trip-detail.html`）
- 必须展示三步计算过程与规则快照（`ruleVersion / baseFactor / modeFactor / pointsRatio`），否则用户无法自证积分正确。
- `PENDING` 显示「核算中，稍后刷新」，不能显示 0 分；`FAILED` 显示原因 +「重新上报」。
- 规则改动不追溯：页面写明「按入账当时的规则版本计算」。

### 4.2 取消订单只由管理员发起（`admin/orders.html`）
- 用户端 `app/orders.html` **不提供取消入口**，只读展示「取消原因」列；需要取消时提示联系运营管理员。
- 取消订单（`CREATED → CANCELLED`）必须选择原因，未选不允许提交；选「其他」时必须填写补充说明。
- 原因与补充说明按 `原因：说明` 落库并写入订单详情，用户端可见；取消后原额返还积分 + 原数量返还库存 + 写 `REVERSE` 流水。
- 重复取消按幂等处理，返回原对象而不是报错。

### 4.3 积分对账（`admin/reconciliation.html`）
- 三态：无差异 / 发现差异 / 读取失败。
- 差异表只读展示 `checkName / expected / actual`，**不提供自动修复**，页面给人工处理步骤。
- 读取失败返回 5xx（50001）并明确「这不代表没有问题」，禁止显示成无差异。

## 5. 工程落地

- 组件：`AsyncBlock`（Vue）接收 `loading / error / empty / forbidden` 四个 slot + `retry` 事件，页面只传数据与回调，避免每页重写。
- 请求层：Axios 拦截器把 401 / 403 / 5xx 归一为 `{ kind: 'auth' | 'forbidden' | 'server' | 'network', code, message }`，组件读 `error.kind` 而不是解析后端文案。
- 路由：`meta.layout` 之外再加 `meta.role`，前端守卫只做体验兜底，后端接口必须独立鉴权。
