# 绿行积分 · 交互流程

> 版本 v1.0　每个流程含：主路径、异常路径、状态机、埋点（可选）

## 0. 全局导航模型

```
登录 ─┬─ USER ─→ 用户端（顶栏：首页 / 行程 / 积分 / 商城 / 我的）
      └─ ADMIN ─→ 管理端（侧栏：概览 / 规则 / 礼品 / 订单 / 用户）
```

- 顶栏右侧固定为「积分余额 + 头像菜单」，任何页面都能看到余额（可核对原则）。
- 管理端左上是返回用户端的入口，避免两个身份混在一个顶栏里。
- 页面跳转不整页刷新；切页保留滚动位置（`scrollBehavior` + `savedPosition`）。

## 1. 登录 / 注册

```
[登录页]
 ├ 输入用户名+密码 → 前端校验非空 → POST /api/auth/login
 │   ├ 200 → 写 token+profile → 按 role 跳转（USER→/，ADMIN→/admin/dashboard）
 │   ├ 401 → 表单下方红字「用户名或密码不正确」（不清空密码框）
 │   └ 423 → 「账号已停用，请联系运营管理员」
 └ 去注册 → [注册页]
     ├ 用户名 4–20 位字母数字下划线，失焦即查重（防抖 400ms）
     ├ 密码 ≥6 位，两次一致，实时显示强度（弱/中/强）
     ├ 未勾协议 → 按钮禁用 + 说明文字
     └ 成功 → 自动登录并跳 `/`，Toast「注册成功，已赠送新人礼」
```

**关键点**：注册与登录共用一个 `AuthCard` 组件；错误提示只在表单内出现，不用弹窗打断。

## 2. 行程上报（核心流程，UC-04）

```
[首页 / 快速上报卡]
 1 选出行方式（公交/地铁/骑行/步行）→ 立即高亮 + 更新公式系数
 2 填里程（数字键盘）与起止时间
    ├ 里程 ≤0 或 >200 → 行内提示，按钮禁用
    ├ 结束时间 < 开始时间 → 行内提示（BR-05）
    └ 时间跨度 >24h → 提示「单次行程不超过 24 小时」
 3 实时预估：减排 kg = max(0, km×(基准−方式))，积分 = floor(减排×比例)
    标注「预估，提交后以服务端核算为准」
 4 点「提交行程」→ 生成 Idempotency-Key → 按钮 loading + 禁用
    ├ 201 → 成功后卡片翻转为结果态（减排 x kg / +y 分），3s 后回到表单
    │        同时余额与「最近行程」即时更新（局部刷新，不整页 reload）
    ├ 409 幂等命中 → 提示「该行程已提交过」，展示原结果链接
    ├ 422 规则校验失败 → 展示服务端原因（如「结束时间早于开始时间」）
    └ 网络错误 → 保留输入 + 「重试」按钮（同一个幂等键）
```

**防重复**：同一 `clientTripId` + 幂等键只允许一条 PENDING/POINTED 记录（BR-06）。
**状态机**：`PENDING → POINTED`（成功）｜`PENDING → REJECTED`（规则不通过，附原因）。

## 3. 行程记录与详情

```
[行程列表] 月份切换 + 方式筛选 + 状态筛选
 ├ 列表行点击 → 右侧 Drawer 显示详情（单号、起止、里程、减免、积分、规则版本）
 └ 筛选无结果 → 空态「没有符合条件的行程」+「清除筛选」
```

列表默认按开始时间倒序，分页 20 条；顶部三个汇总数字随筛选条件联动（本月行程/减排/积分）。

## 4. 积分明细与对账（UC-06）

```
[积分页]
 余额卡（可用 / 累计获得 / 累计兑换）
 流水列表：类型图标 + 描述 + 时间 + 变动值 + 变动后余额
 筛选：全部 / 获得 / 兑换 / 冲正；时间范围
 底部：对账说明（「余额 = 全部流水之和，若有疑问请联系运营」）
```

**设计要点**：每条流水都带「变动后余额」，用户可自行逐行核对；冲正条目用琥珀色，退货用中性色。

## 5. 兑换礼品（UC-07，含并发）

```
[商城列表] → 点卡片 → [礼品详情]
 校验（前端预检，仅提示不拦截）：
   ├ 积分不足 → 按钮禁用 + 「还差 320 分」
   ├ 库存 0   → 按钮禁用 + 「暂时缺货」
   └ 当日次数用尽 → 按钮禁用 + 「今日已达兑换上限」
 点「立即兑换」→ 底部确认弹层（礼品、消耗积分、兑换后余额）
   └ 确认 → POST /api/orders（幂等键）→ 按钮 loading
       ├ 201 → 弹层切成功态 →「查看订单 / 继续逛逛」
       ├ 409 积分不足（并发扣减）→ 就地红字「积分已被其他操作占用，请刷新」
       ├ 409 库存不足 → 提示并刷新商品库存
       └ 5xx → 保留弹层 + 重试
```

**并发**：前端不做乐观扣减，成功后以服务端返回的余额为准（BR-08）。

## 6. 订单：取消与履约

```
用户侧：[我的订单] 页签 全部/待处理/已履约/已取消
 └ 待处理订单 → 「取消订单」→ 二次确认 → 成功后状态变「已取消」，金额显示 +N 分·已退还
管理侧：[订单处理] 表格 → 行内「履约」「取消」
 ├ 履约（仅 CREATED 可点）→ 确认框 → 状态变「已履约」
 └ 取消（仅 CREATED 可点）→ 确认框 → 状态变「已取消」并冲正积分、归还库存
```

**状态机**：`CREATED →(履约) FULFILLED`｜`CREATED →(取消) CANCELLED`；后两个状态不可逆，按钮置灰并提示「已结束的订单不可再操作」。

## 7. 管理端：新建碳核算规则（UC-09）

```
[规则页] → 「新建规则」
 表单：出行方式、基准因子、方式因子、积分比例、生效时间、变更原因（必填）
 ├ 试算器实时联动：输入里程 → 显示减排量与积分（校验因子是否合理）
 ├ 同一方式同一日已有生效规则 → 提交时后端拒绝，前端提示「该方式当日已有生效规则」
 └ 成功 → 列表插入新版本，旧规则自动归档（状态变「已归档」），Toast 提示生效时间
**规则不可改，只能新建版本**：历史行程永远引用当时版本（可追溯）。
```

## 8. 错误与空态统一话术

| 场景 | 文案 |
| --- | --- |
| 网络失败 | 网络开小差了，请检查连接后重试 |
| 会话过期 | 登录已过期，请重新登录（自动跳登录并带回跳地址） |
| 无权限 | 你没有访问该页面的权限 |
| 业务失败 | 直接展示服务端 `message`，不加「错误：」前缀 |
| 空数据 | 还没有行程记录，去首页记录第一段绿色出行吧 |

## 9. 交互细节清单（验收用）

- [ ] 所有提交类按钮点击后 300ms 内进入 loading，且不可重复点击
- [ ] 表单错误在失焦与提交时都校验，错误文案紧贴字段
- [ ] 列表筛选变化后页码重置为 1
- [ ] 弹层打开时焦点进入弹层，Esc 关闭，关闭后焦点回到触发按钮
- [ ] 危险操作二次确认，确认按钮文案为具体动作
- [ ] 金额/积分变化有 200ms 数字滚动（可选，尊重 reduced-motion）
