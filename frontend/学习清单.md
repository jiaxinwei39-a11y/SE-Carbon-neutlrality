# 给你的学习清单（小白版，按"先能跑、再能改、最后能讲"排序）

> 目标：两周内能独立改这个 demo 的页面、能对着老师讲清每个设计决定为什么这么做。
> 每一条都写了"为什么学"和"在项目里看哪个文件"，不要从教程第一章开始啃。

## 第 0 层：先会跑（半天）

| 要会 | 为什么 | 在项目里看 |
| --- | --- | --- |
| 命令行 `cd`、执行 `npm run dev` | 所有前端工作都从这开始 | README「怎么启动」 |
| `npm install` 装依赖、`node_modules` 不能提交 | 依赖不进 Git 是行业底线 | `.gitignore` |
| 看懂报错：**文件名:行号: 错误信息** | 90% 的求助信息就是这一行 | 故意改错一个字试试 |

**动手验证**：把 `src/views/user/ProfileView.vue` 里"个人资料"改成"我的资料"，保存，页面自动变了 —— 这就是热更新。

## 第 1 层：三件套（3 天）

### 1. HTML/CSS 只学够用的
- 盒模型、flex（`display:flex` + `gap` + `justify-content` + `align-items`）——本项目 90% 的布局靠它
- 类名怎么起作用：打开 `src/styles/components.css`，搜 `.card`，对照页面看效果
- **不要**去背 CSS 属性大全，用到再查

### 2. JavaScript 的 ES6 部分
- `const/let`、箭头函数、模板字符串
- 数组方法：`map`（变形）、`filter`（筛选）、`find`、`reduce`（累加）——列表页全靠它们
- `async/await` + `try/catch`：为什么每个请求都要 try/catch（看 `src/views/user/MallView.vue`）
- 解构 `const { items, total } = data`

### 3. Vue 3 的四个核心（这个必须真懂）
| 概念 | 一句话 | 项目里的例子 |
| --- | --- | --- |
| `ref` 响应式 | 变量变了，页面自动更新 | `src/views/user/PointsView.vue` |
| `v-model` | 表单双向绑定 | `src/components/TripForm.vue` |
| `v-for` / `v-if` | 循环、条件渲染 | 任意列表页 |
| 组件 + props/emit | 父传子用 props，子调父用 emit | `src/components/AppButton.vue` |

> 判断自己会不会：能不能不看代码说出"用户在输入框打字 → 我改了哪个 ref → 哪个元素跟着变"。

## 第 2 层：这个项目的骨架（3 天）

按这个顺序读，每个文件 20 分钟：

1. `src/router/index.ts` —— 网址和页面的对应关系，`meta.requiresAuth` / `meta.role` 是权限
2. `src/stores/user.ts` —— 登录态为什么要"全局"存一份
3. `src/api/http.ts` —— 请求发出去到回来，中间被拦截器做了什么（加 token、判 401、校验 code）
4. `src/api/mock.ts` —— 假后端长什么样；**接后端就是把这个文件换掉**
5. `src/types/index.ts` —— 数据结构即"页面和后端的合同"

读完能回答：*"为什么页面里没有一处 axios，也能拿到数据？"*（答案：api 层封装）

## 第 3 层：工程习惯（贯穿，别单独学）

| 习惯 | 具体做法 |
| --- | --- |
| 先跑通再优化 | 页面先静态渲染，再连数据 |
| 三态必做 | 每个请求都有 加载中 / 空 / 失败，缺一个就是 bug |
| 不要写魔法数字 | 常量放 `src/utils/constants.ts` |
| 颜色不写进组件 | 只用 `styles/` 里的类，改主题只改 token |
| 提交信息说人话 | `feat: 行程列表增加方式筛选` |
| 文档与代码同步 | 改了字段就改 `docs/api-contract.md` |

## 第 4 层：能讲（答辩前 1 天）

老师大概率问这 6 个，准备好答案（都在 README 第六节的表里）：

1. 为什么用 hash 路由？→ Electron `file://` 下 history 模式刷新 404
2. mock 数据算"造假"吗？→ 接口契约是真的，只有数据源是假的；`VITE_DATA_SOURCE` 一个开关就换真后端
3. 幂等键解决什么？→ 用户手抖点两次、网络超时重试，不能重复加分
4. 为什么减排量存 9 位、显示 6 位？→ 计算精度不能被展示精度污染
5. 对账页"读取失败"为什么不能显示 0 差异？→ 未知 ≠ 一致，会把真问题藏起来
6. 前端做了权限，后端还要做吗？→ 必须，前端的守卫只是体验，接口鉴权在后端

## 明确不用学（省时间）

- Webpack 配置（用 Vite 了）、Sass/Less（本项目原生 CSS + 变量）
- SSR/Nuxt、微前端、Web Components
- 复杂状态管理方案（Pinia 够用）
- UI 组件库源码（本项目没用）

## 两周节奏建议

| 时间 | 做什么 |
| --- | --- |
| 第 1–2 天 | 能跑起来 + 改文案/颜色/布局不出错 |
| 第 3–5 天 | 独立加一个"行程列表按里程排序"的小功能 |
| 第 6–8 天 | 读完第 2 层的 5 个文件，画一张自己的数据流图 |
| 第 9–12 天 | 把 mock 关掉（`VITE_DATA_SOURCE=api`）看哪里白屏，记录需要后端配合的点 |
| 第 13–14 天 | 练演示脚本 3 遍，准备第 4 层的 6 个问题 |

## 遇到问题怎么问（这条最实用）

把这三样一次发出来，别人 3 秒能定位：
1. 我做了什么（点了哪个页面/按钮）
2. 期望什么、实际什么（截图）
3. 控制台报错的那一行（F12 → Console，复制红色文字）
